O que precisa ser cadastrado · Na ordem certa · Antes da apresentação

Ordem importa. Cada cadastro depende do anterior. Pular etapas vai quebrar o fluxo da demo. Siga a sequência exata abaixo.
1

Estrutura da empresa

Base de tudo. Sem isso, nenhum outro cadastro funciona.

Empresa (company)

Obrigatório

Nome da empresa, CNPJ, configurações gerais. Já deve existir via Supabase Auth.

Supabase → tabela companies

Unidades (cozinhas + CD)

Obrigatório

Cadastre pelo menos 1 cozinha e 1 CD (Central de Distribuição). Defina nome, tipo e número de colaboradores — esse número é usado para calcular per capita.

Configurações → Unidades
Para demo: 1 cozinha com 50 colaboradores + 1 CD é suficiente.

Usuários e perfis

Obrigatório

Crie pelo menos 3 usuários com perfis diferentes para mostrar o controle de acesso na demo: CEO, Nutricionista e Estoquista.

Configurações → Acesso
2

Fornecedores

Todo pedido de compra precisa estar vinculado a um fornecedor. É a dependência mais crítica do módulo de Compras.

Onde cadastrar fornecedores

Obrigatório

No Yassuo, fornecedores são cadastrados dentro do módulo de Compras. O caminho exato depende de como o Lovable estruturou o menu, mas siga esta ordem de busca:

1º
Menu lateral → Compras → Fornecedores
Caminho mais comum. Procure "Fornecedores" como submenu de Compras.
2º
Menu lateral → Configurações → Fornecedores
Alguns apps colocam fornecedores em configurações gerais.
3º
Supabase → Tabela suppliers
Se não houver tela no app, cadastre direto no Supabase. Abra o projeto → Table Editor → suppliers → Insert Row.
Se não encontrar a tela: envie um prompt no Lovable pedindo para criar uma tela de cadastro de fornecedores em Compras → Fornecedores antes da demo.

Produtos / Insumos

Obrigatório

Nome, marca, unidade de medida (kg, L, un), categoria, estoque mínimo e custo unitário. O custo é usado para calcular o custo real da refeição no Painel CEO.

Estoque → Novo Produto

Lotes de estoque inicial

Obrigatório para FEFO

Cada produto precisa de pelo menos 1 lote com quantidade, data de validade e código. Sem lote, o FEFO não funciona e o estoque aparece zerado.

Nutri → Pratos → Criar Prato → Editar Ficha

Funcionalidade perdida

Recebimento — importação de NF-e em PDF sumiu

Antes era possível importar a nota fiscal em PDF além do XML. Após o refinamento visual do módulo de Recebimento, apenas o XML permaneceu. O PDF é mais usado no dia a dia — a maioria dos fornecedores envia por WhatsApp.

Impacto: O estoquista não consegue processar notas que chegam em PDF. Precisa digitar manualmente ou esperar o XML — o que não é realista na operação.
Prompt para o Lovable
Quero reativar a importação de NF-e em PDF no módulo de Recebimento Digital do Yassuo. Contexto: - Antes existia a opção de importar NF-e em PDF, além do XML - Após o refinamento visual do Recebimento, só o XML ficou disponível - O PDF precisa voltar — é o formato mais usado pelos fornecedores no dia a dia Como implementar: Opção recomendada (mais estável para produção): - Upload do PDF → sistema tenta extrair dados via OCR (tesseract.js ou biblioteca equivalente) - Se o OCR funcionar: preencher os campos automaticamente para o usuário confirmar - Se o OCR não conseguir ler: mostrar mensagem clara "Não foi possível ler automaticamente" + formulário para preenchimento manual UX esperada: - Dois botões na área de importação: "Importar XML" e "Importar PDF" - Ao selecionar PDF: tela de upload → progresso de leitura → campos preenchidos ou formulário manual - Mensagem de estado clara em cada etapa - Empty state se nenhum arquivo for selecionado Campos que precisam ser extraídos (ou preenchidos manualmente): - CNPJ do fornecedor - Número da nota (NF-e) - Data de emissão - Itens: nome do produto, quantidade, unidade, valor unitário - Valor total da nota Regras: - Não alterar nada do fluxo XML que já funciona - Não alterar nada visual além do botão de PDF - Manter dark premium, vermelho Yassuo, ícones Lucide - Priorizar estabilidade — se o OCR for arriscado, pode ser apenas upload + preenchimento manual assistido Entregável: Recebimento com ambas as opções (XML e PDF) funcionando, sem regressão do XML existente.

UX / Usabilidade

Fichas técnicas — campo "fator de correção" sem explicação

O fator de correção é um campo técnico da nutrição que a maioria das pessoas não conhece. Na ficha técnica de cada prato, esse campo aparece sem tooltip ou explicação — a nutricionista não sabe o que colocar.

Impacto: Campo preenchido errado = custo calculado errado = KPI do Painel CEO errado. É um erro silencioso que afeta toda a cadeia de dados.
Prompt para o Lovable
Preciso melhorar a usabilidade do campo "Fator de Correção" nas fichas técnicas de pratos do Yassuo. Problema: O campo aparece na ficha técnica mas sem nenhuma explicação do que é ou como calcular. A nutricionista não sabe o que colocar, deixa em branco ou coloca 1 por padrão — o que pode gerar erro no custo calculado. O que quero: 1. Adicionar um tooltip (ícone de interrogação ao lado do campo) com a explicação: "O Fator de Correção (FC) indica quanto do alimento bruto é aproveitável. Exemplo: 1 kg de frango bruto → 0,72 kg limpo → FC = 1,38 (1 ÷ 0,72). Se você não sabe o FC, use 1.0 como padrão — significa que 100% do ingrediente é aproveitado." 2. Adicionar exemplos práticos como placeholder ou hint abaixo do campo: - Frango peito: 1.38 - Feijão cru: 1.00 - Cebola: 1.10 - Cenoura: 1.14 - Arroz cru: 1.00 3. Se o campo estiver vazio ao salvar, preencher automaticamente com 1.0 e mostrar aviso: "Fator de correção não informado. Usando 1.0 (100% aproveitável). Atualize se souber o valor correto." Regras: - Não alterar a lógica de cálculo existente - Não alterar nada visual além do tooltip e hint - Manter identidade Yassuo (dark premium, Lucide, sem emojis) Entregável: Campo "Fator de Correção" com tooltip explicativo, exemplos e fallback automático para 1.0.
Acesso / Testes

Como trocar senha de cada perfil

Por que só a sua senha funciona? Usuários criados no app têm e-mail registrado no Supabase Auth, mas não têm senha definida — eles precisam de um link de convite ou de redefinição. Use um dos dois métodos abaixo para resolver isso.
1

Método Supabase Dashboard — mais fácil

Funciona quando o e-mail do usuário existe de verdade (você consegue receber o e-mail).

3

4

5

Se o e-mail é fictício (ex: nutri@yassuo.com) e você não tem acesso a ele, use o Método 2.

O que revisar: - consistência de tipografia em todos os módulos (tamanho, peso, hierarquia) - consistência de cores (vermelho Yassuo como identidade, âmbar para alertas, verde para saudável) - consistência de cards (border-radius, sombra, hover, estado ativo) - consistência de ícones (todos Lucide, sem emojis) - consistência de empty states (mesmo padrão de ícone + título + microcopy + CTA) - consistência de botões (mesmo estilo de CTA primário em todos os módulos) - consistência da navegação (sidebar, bottom nav, breadcrumb, header) - consistência de spacing e padding entre seções - verificar se algum módulo ainda parece "mais antigo" ou "destoante" da direção geral Se encontrar inconsistências: - listar os módulos com problema - aplicar correção alinhando ao padrão já estabelecido - não criar nova direção, só harmonizar com o que já existe Direção final obrigatória: - dark premium forte - vermelho Yassuo como assinatura visual do sistema - sensação de plataforma coesa, profissional, premium e confiável - app que transmite: "isso foi feito com intenção" Entregável: relatório de inconsistências encontradas + correções aplicadas + confirmação de que o app está pronto para apresentação.

Script de 5 minutos

Fala sugerida incluída
1
Abertura — O problema que o Yassuo resolve 30 seg
Tela: Painel CEO
Fala sugerida

"Gestão de cozinha industrial hoje é planilha, WhatsApp e achismo. O Yassuo centraliza tudo — cardápio, estoque, custo, pedidos e desperdício — numa plataforma que qualquer gestor entende em segundos."

Abra o app e mostre o Painel CEO com os KPIs acesos
Destaque: total de refeições, custo por prato e alertas ativos
2
O cérebro da operação — Painel da Nutri 1 min
Tela: Painel da Nutri
Fala sugerida

"Aqui está o centro de comando da nutricionista. Ela vê de relance o que está planejado, o que está faltando e o que precisa de ação imediata — sem abrir planilha nenhuma."

Navegue para Nutri → Painel
Mostre os KPIs: semana planejada, pedidos pendentes, estoque baixo
Clique em um alerta para mostrar o roteamento automático
Momento WOW: clicar no alerta de estoque baixo e ele navegar direto para o item no estoque. Mostra inteligência do sistema.
3
Da refeição ao pedido — em 3 telas 1 min 30 seg
Telas: Cardápio → Insumos → Pedido
Fala sugerida

"O cardápio da semana está montado. O sistema automaticamente calcula o que precisa ser comprado — por produto, por quantidade, com o que já tem no estoque descontado. Um clique gera o pedido de compra."

Abra Cardápio Semanal — mostre os dias planejados e os dias em aberto
Navegue para Planejamento de Insumos — mostre a barra de cobertura por item
Clique no botão vermelho Gerar Pedido de Compra
Mostre o pedido criado com os itens, quantidades e fornecedor vinculado
Momento WOW: o pedido sendo gerado automaticamente. Mostra que o sistema pensa junto com o operador.
4
Estoque inteligente — FEFO em ação 1 min
Tela: Estoque
Fala sugerida

"O estoque usa lógica FEFO — o primeiro a vencer é o primeiro a sair. Isso evita desperdício de alimento e multa sanitária. O sistema destaca automaticamente o que está crítico."

Abra Estoque — mostre os 4 KPIs no topo (total, críticos, venc. próximo, zerados)
Destaque o banner vermelho de ruptura (item abaixo do mínimo)
Mostre o badge FEFO num item e explique: "é este lote que a cozinha deve usar primeiro"
5
Fechamento — Visão do CEO e próximos passos 30 seg
Tela: Painel CEO
Fala sugerida

"O gestor abre o app e sabe exatamente o que está acontecendo na operação — custo, desperdício, alertas, sem depender de relatório semanal. Isso é gestão em tempo real."

Volte ao Painel CEO
Mostre o radar financeiro e o custo real da refeição
Abra para perguntas — tenha os dados do modelo de negócio prontos

Dicas para a apresentação
★
Não leia o roteiro em voz alta. Use-o como guia mental. A fala deve soar natural.
★
Deixe o investidor tocar. No momento WOW da cena 3 (gerar pedido), dê o celular para ele clicar. Participação cria conexão.
★
Se travar, volte ao Painel CEO. Ele resume tudo e é o visual mais forte do app.
★
Termine com uma pergunta. "O que você quer ver com mais detalhe?" — isso mantém o investidor engajado e revela o que importa para ele.
